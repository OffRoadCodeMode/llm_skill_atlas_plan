# DR-001 — SQLite for the dedup store

## Status
Accepted

## Context
Feed entries must be deduplicated across runs so the digest only contains new
items. The store lives wherever the CLI runs (VPS or local), must survive
restarts, and hold ~10k entries/year at most.

## Options considered
1. **SQLite file** — zero ops, single file, ships with Python; no concurrent
   writers ever expected (single cron process).
2. **JSON file + set of guids** — simpler still, but no querying and easy to
   corrupt on crash; re-parsing on every run.
3. **Postgres** — overkill; violates "boring technology" and the $5/mo budget.

## Decision
SQLite, one table `entries(guid TEXT PRIMARY KEY, source, title, url, published)`,
wrapped by a thin `store.py` module so a swap stays possible.

## Consequences
- No operational dependencies; backup is copying one file.
- If nightowl ever wants multi-process writes, revisit (unlikely — a non-goal).
