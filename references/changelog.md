# Changelog — Atlas

All notable changes to the Atlas framework itself. Format: reverse chronological.
Bump the `version:` field in `SKILL.md` frontmatter (semver) for convention changes;
a major bump signals breaking convention changes.

## 1.1.0 — 2026-10-26

Marketplace-readiness release (prepared for sale on Agensi). No framework
conventions changed — additive packaging, licensing, and host coverage.

- **License:** replaced MIT with the **Atlas Personal License** — use in
  unlimited projects with any agent; no redistribution, resale, or public
  sharing. Paid distribution requires it.
- **SKILL.md frontmatter:** description retuned for reliable triggering —
  explicit trigger phrases buyers actually say ("plan a project", "project
  roadmap", "track decisions/ADRs", "pick up a project after a break") plus a
  negative trigger ("Do not use for one-off drafts or general Q&A").
- **New: `examples/example-project/`** — a small, internally consistent
  example planning repo ('nightowl', an RSS digest CLI) showing the v1.0.0
  conventions in practice: dashboard scoreboard, one system in design phase
  with a DR and a concluded spike (spec + results), one workstream, the
  overview roll-ups mirrored, a conception research doc, and session files.
  Shows buyers what Atlas output looks like before they run it.
- **New host adapters** (six-capability contract, from vendor docs):
  `hosts/claude-code.md`, `hosts/cursor.md`, `hosts/codex-cli.md`,
  `hosts/gemini-cli.md`, `hosts/openclaw.md` — covering the mainstream
  marketplace agents. OpenClaw gets a first-class scheduled-audit recipe via
  its built-in Automations. SKILL.md host table updated accordingly.
- **Packaging:** `.gitattributes` added (`export-ignore` for dotfiles);
  README documents the release recipe —
  `git archive --format=zip --prefix=atlas/ HEAD -o atlas-<version>.zip`.

Projects onboarded under 1.0.0 need no changes; new adapters and the example
are available going forward.

## 1.0.0 — 2026-10-26

**Breaking.** `project/shared/` replaced by `overview/` + `conception/`;
roll-ups are now maintained **inline** (updated in the same action as their
source); audit becomes a **read-only verifier**. Projects onboarded under 0.x
need a one-time migration (below).

- **BREAKING — `project/shared/` is gone**, split by lifecycle:
  - **`project/overview/`** — permanent cross-project registers & roll-ups:
    (NEW) `TASKS.md` — global task roll-up, a full mirror of every system and
    workstream `TASKS.md`; (NEW) `DECISIONS.md` — index of every Decision
    Record; plus glossary, open-questions, risks, costs, system-map (moved from
    `shared/` unchanged in role).
  - **`project/conception/`** — the pre-system space; `research/` moves here
    from `shared/research/`. Expected to drain as systems emerge and absorb it.
- **Inline maintenance is the new core rule** (SKILL.md principle 4): any
  change to a local register — task tick, DR capture, risk, OQ, cost, system
  frontmatter, relationship edge — is mirrored to its roll-up **in the same
  action**, never deferred. Local registers remain the source of truth;
  roll-ups are redundant, regenerable views.
- **Audit is now a verifier, not a regenerator.** It no longer rebuilds INDEX
  Contents, dashboard rows, or roll-ups, and auto-fixes nothing. It verifies
  that inline discipline held and reports findings with suggested inline
  corrections; it may *offer* user-approved regeneration of a badly drifted
  roll-up via orchestrator. Audit writes only its own records: conflict
  reports (`sessions/conflicts/`) and `.atlas-audit-state`.
- **Decisions get an index and a cheap conflict scan.** `overview/DECISIONS.md`
  is updated at DR-capture time; the pre-DR conflict scan (decision-record
  agent) checks the Active table before a new DR is written. Audit check 16
  becomes the backstop and uses the index as its fast path.
- **Template changes:** new `templates/overview/TASKS.md` and
  `templates/overview/DECISIONS.md`; dashboard Systems table gains a `Tasks
  (open)` column and its comment block switches from "REGENERATED by audit" to
  "updated INLINE, verified by audit"; system/workstream TASKS templates state
  the mirror rule; system INDEX/Risks/Costs/AGENTS templates repointed.
- **Audit checklist:** new check 19 (roll-up integrity — TASKS mirror and
  DECISIONS index vs sources); check 14 now also compares `budget.xlsx` totals
  against `costs.md` (previously promised in the research agent but never
  specified — doc drift fixed); check 17 paths updated to `conception/research/`.
- **session-continuity:** resume now skims `overview/TASKS.md` as the
  actionable "what's next"; end-of-session step 3 becomes *verify the roll-ups
  held* (a spot-check, not a deferred maintenance pass).
- **orchestrator:** index/roll-up regeneration is an explicit, user-approved
  repair (`/orchestrator:rebuild`), replacing the previously dangling
  `/orchestrator:sync` reference.
- **Simplification pass — fewer files, all earning their place:**
  - **Pure-MOC `INDEX.md` files cut** (root, `project/`, `systems/`,
    `workstreams/`, `overview/`, `conception/`, `sessions/`). A bullet list of
    links to files already visible in the folder listing is permanent
    maintenance cost for zero information. System and workstream `INDEX.md`
    stay — they hold real metadata, not links.
  - **Per-system `CHANGELOG.md` cut.** The record lives in git history, DRs,
    and session logs — no third overlapping history to maintain.
  - **`DASHBOARD.md` slimmed to a scoreboard** (Systems / Workstreams /
    Milestones + links). Top Risks, Costs, and Recent Decisions were pure
    mirrors of overview registers — link, don't copy.
  - **Deferred seeds.** Onboarding no longer creates empty files. `glossary`,
    `open-questions`, `risks`, `costs`, `system-map`, and per-system
    `AGENTS.md` are all created on demand; container folders appear with their
    first content. Day one is ~7 files.
- **SKILL.md:** principles restated (inline roll-ups; audit verifies), router
  rows added for the task and decision roll-ups, version 1.0.0.

### Migration (projects onboarded under 0.x)

Apply via the governance "After pulling a skill update" flow:

1. `git mv project/shared project/overview`; move `overview/research/` to
   `project/conception/research/`.
2. Repoint `shared/` links to `overview/` (audit check 1 catches stragglers).
3. Delete pure-MOC `INDEX.md` files (root, `project/`, `systems/`,
   `workstreams/`, `overview/`, `conception/`, `sessions/`) and per-system
   `CHANGELOG.md` files (history lives in git).
4. Slim `DASHBOARD.md` to the scoreboard template (drop Top Risks / Costs /
   Recent Decisions sections).
5. Create `overview/TASKS.md` (mirror all local `TASKS.md` contents and counts)
   and `overview/DECISIONS.md` (one row per existing DR) from the new
   templates. Optionally delete any still-empty overview registers — recreate
   on demand.
6. From here on, maintain roll-ups inline (same action as the source change).
7. Stamp `atlas: 1.0.0` in root `AGENTS.md` and the dashboard footer.

## 0.10.0 — 2026-10-26

Software pack gains **spikes**: timeboxed, hands-on experiments that answer
technical questions research alone can't settle. Additive, optional — no changes
to core conventions.

- **New: `references/domains/software/spikes.md`** — defines the convention.
  Spikes live in a **system-level `spikes/` folder**, separate from `research/`,
  one folder per spike. The **spec/results split** is the core rule: `spec.md`
  (question, hypothesis, success criteria, approach, timebox) is written *before*
  running; `results.md` (verdict vs criteria, measurements, next steps) is
  written at conclusion and is immutable thereafter.
- **Code location is a spec-time user decision**, recorded in spec frontmatter:
  `code_location: in-repo` (code in `spikes/<name>/code/`) or `external`
  (recorded in `code_ref:` — project's code repo or scratch repo).
- **New templates**: `references/domains/software/templates/spike-spec.md` and
  `templates/spike-results.md`.
- **phases.md**: the software design-phase exit gate now names the concrete
  evidence — a concluded `spec.md` + `results.md` per spike for risky components.
- **SKILL.md**: router gains a "Run / conclude a technical spike" row; version
  bumped to 0.10.0.

No backfill needed for existing projects — spikes folders are only created when
a spike is proposed. Projects onboarded under earlier versions may adopt the
convention going forward.

- **SKILL.md**: "How to load skill files in Hermes" → "Host environments
  (identify yours first)" with host table; **activation prompt now loads the
  host file as step 2** (before conventions/onboarding); router gains a
  host-file row; "Complementary Hermes skills" → "Complementary skills"
  pointing at host files.
- **README.md**: install instructions for Hermes, Devin (global + project), and
  any other agent; usage flow notes host-file loading; repo tree includes
  `references/hosts/`; Contributing now lists host adapters alongside domain
  packs; status bumped to 0.9.0.
- **onboarding.md / session-continuity.md**: complementary-skills check, audit
  cadence, and memory pointer now route through the host file.
- **conventions.md**: Hermes mentions → host-agnostic wording.
- **governance.md**: new rule 6 ("host specifics stay in host adapters") and a

  host file must answer, plus the `host:` commit prefix.
- **agents/research.md / diagram.md**: `skill_view(...)` calls → "load via the
  host's skill mechanism (see your host file)".
- **agents/orchestrator.md**: `delegate_task`/`tasks` specifics moved to
  `hosts/hermes.md`; generic delegation patterns remain.
- **agents/audit.md**: Hermes `cronjob(...)` wrapper moved to `hosts/hermes.md`;
  the **canonical audit prompt now lives here** (in the audit agent's own spec)

Hermes sessions just load `references/hosts/hermes.md` first.

## 0.1.0 — 2026-07-25

Initial release. Minimal-but-complete framework (*prove before scaling*).

- Router `SKILL.md` with activation prompt and planning-verb vocabulary.
- Core guides: `references/conventions.md`, `references/onboarding.md`,
  `references/system-lifecycle.md`, `references/session-continuity.md`,
  `references/governance.md`.
- Generic agents: `orchestrator`, `session-log`, `decision-record`, `audit`
  (fully specified); `research`, `diagram`, `scope-check` (stubs, grow as needed).
- Domain packs: `software` (SDLC phases, system types, templates, traceability +
  sync-tasks agents) and `general` (plan → research → design → execute → review).
- Templates: generic system-folder scaffold (incl. `risks.md` + `costs.md`) and
  top-level templates (mission, decision-record, decisions, open-questions, risks,
  costs, session-log, dashboard).
- Costs & risks are core canon: optional/emergent registers at project level and
  optionally per-system, rolled up to the dashboard by `audit`.
- Inter-system relationships are core canon: `project/shared/system-map.md`
  (Mermaid graph + relationship register) is the source of truth, mirrored by a
  `Relationships` section in each `OVERVIEW.md` and reconciled by `audit`
